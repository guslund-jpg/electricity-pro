### November 1: two-hour price trend smoke check

After the clean ZIP installation, the synthetic instance initially had only lab
sensors and no Price direction entity. The code creates forecast entities only
when a Nord Pool forecast source is configured. The maintainer then configured
Nord Pool; the screenshot showed SE3, SEK and VAT included.

- Existing entity `sensor.electricity_pro_price_direction` appeared with state
  `rising`, `trend_duration_minutes: 120` and `stable_tolerance_percent: 2`.
- First period: 06:35:50.937179–07:35:50.937179 UTC, average approximately
  2.5914894 SEK/kWh; second period immediately followed for one hour, average
  approximately 2.6540441 SEK/kWh.
- Delta approximately 0.0625548 exceeded tolerance approximately 0.0530809:
  `rising` matches the two-hour contract.
- After 20 minutes, the maintainer confirmed the hour boundaries advanced.
- `price_completeness: partial` describes cost-component scope, not missing
  time intervals. This observation is not a complete-bill verification.

Result: PASS for entity creation after forecast configuration, the observed
rising calculation/attributes and scheduled refresh. This is not a manual test
of every direction, tolerance boundary, DST or missing-forecast case; automated
tests cover those contracts. Both dashboard presentations remain unreviewed.
