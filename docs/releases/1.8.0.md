# Electricity Pro v1.8.0 beta and upgrade notes

**Status: preparing v1.8.0b1; not published.** This is the first planned beta
toward v1.8.0. Use a separate test installation for beta testing. The
[latest published release](https://github.com/guslund-jpg/electricity-pro/releases/latest)
continues to identify the stable version; changing the source manifest does not
publish a release or make it a stable Marketplace/HACS update.

Requires **Home Assistant Core 2026.9.0 or newer**. The current Core baselines
use Python 3.14; the minimum remains unchanged.

## Upgrade and dashboards

Before testing, make a recovery backup including HA configuration, Electricity
Pro settings/statistics and the Recorder database. Keep the existing integration
entry. Install the approved versioned candidate and restart Home Assistant;
check live readings, forecasts, existing IDs/settings and accumulated totals.
Do not delete/recreate the entry or clear statistics to perform an upgrade.
Rollback uses the matching recovery backup; downgrading code alone has not been
validated as a saved-data rollback.

Dashboard examples are copied separately. Replace an existing dashboard's raw
YAML with the example for its language and variant, carrying over custom entity
IDs, scales and other local changes. An integration upgrade does not rewrite
dashboards. Standard uses built-in cards; Enhanced retains Mushroom and
ApexCharts Card. See the [dashboard guide](../../examples/dashboards/README.md).

Cost-component history starts when component data was recorded. Older costs
remain explicitly unsplit, and earlier monthly chart data is not reconstructed
from Recorder. Partial months and missing intervals retain coverage
notes. The chart covers variable import costs; fixed fees and separate export
compensation are not added to its stacks. Estimates exclude unconfigured fees.

## Fixed export compensation is experimental

Select a compatible directional lifetime export register and separately declare
its fixed price, currency, VAT and included compensation components. Import
prices, signed net power, production and battery readings are not substitutes.
See [configuration and limits](../guides/production-export.md#fixed-export-price-beta).

The amount is signed: 2 kWh at −0.20 SEK/kWh gives **−0.40 SEK**, a cost for
export. Known zero stays available; missing data does not become zero. Import
costs remain separate. An interval needs one price covering its full duration;
an interval spanning a price change remains unpriced. Price changes preserve
earlier bookings and do not retrospectively price earlier gaps.

Coverage always remains partial, including when all observed export was priced.
These estimates are not a complete bill or verified supplier settlement.
Mixed currency/VAT/component declarations can withhold a period's amount.
Already booked values can remain visible during source gaps or with pricing
disabled, accompanied by status attributes/notes.

A new local day can temporarily show unavailable until its first priced interval
is checkpointed. A known-zero run observed a **60.6-second** gap at midnight;
this is an observation, not an availability bound. Publication follows saved
checkpoints. Abrupt power loss can lose updates since the last successful write,
normally up to one minute with functioning storage.

Real nonzero export, signed live compensation, nonzero partial pricing and a live
month boundary remain unverified. Physical solar/battery evidence and agreement
with actual compensation await an equipped beta tester in
[#335](https://github.com/guslund-jpg/electricity-pro/issues/335) and
[#241](https://github.com/guslund-jpg/electricity-pro/issues/241).

## Outside this beta

- Demand-charge invoices, hourly grid-import collection and tariff estimates
  from #414–#416 were reverted by #417. That part of #165 remains paused.
- Provider-independent monthly peak-hour statistics (#312) are parked and
  excluded from v1.8.0. Existing configured provider peak-hour sensors retain
  their meaning and identities.
- Supplier/market-linked export prices, site-balance calculations, battery
  control and flexible-load recommendations remain future work.

## Validation and publication

The [validation record](../validation/v1.8.md) separates existing source-build
checks from the versioned beta's pending package smoke test. Core **2026.9.0**
and **2026.10.4** remain the full automated baselines. Current stable Core
[2026.11.2](https://github.com/home-assistant/core/releases/tag/2026.11.2) is used
for the configured manual instance. The latest
[test harness 0.13.375](https://github.com/MatthewFlamm/pytest-homeassistant-custom-component/releases/tag/0.13.375)
still targets 2026.10.4, so manual results do not establish a full automated
integration suite on 2026.11.2. See the [support review](../development/contributing.md#v180-beta-review--21-november-2026).

The release-preparation PR records candidate commit/package fingerprints and
checks. Final candidate installation, merge and publication each require the
maintainer's applicable approval; this document records no publication approval.

After approval and publication, mark **v1.8.0b1** as a GitHub **pre-release**.
Testers opt in with the repository's Pre-release switch and select that version
in Marketplace/HACS. Follow the [official pre-release guide](https://contributors.home-assistant.io/marketplace/guides/releases/#pre-releases).
The beta must not replace the published stable release designation.
