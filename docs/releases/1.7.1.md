# Electricity Pro v1.7.1 release and upgrade notes

Released on **6 November 2026**. v1.7.1 fixes a saved Nord Pool area that could
be lost when saving an unrelated option in a Custom entry. It also bounds
routine statistics checkpoints and compacts power coverage during continuous
meter updates. See the [v1.7.1 release](https://github.com/guslund-jpg/electricity-pro/releases/tag/v1.7.1).

## Changes

- Keep a valid selected Nord Pool area when saving other Custom settings.
  Single-area entries use their configured bidding area directly. (#362)
- Batch routine statistics writes at a fixed one-minute deadline. Flush pending
  statistics for reload, shutdown, rollover and resets. (#365, #366)
- Merge overlapping and adjacent power coverage ranges used by Average Power
  Today and the timing score. Retain gaps and support existing snapshots. (#367)
- Share the Nord Pool area lookup and saved-area resolution between Custom and
  Tibber flows. (#361)
- Run the full Python suite in CI on the minimum supported Core version. (#360)

## Home Assistant support and upgrade

The minimum is **Home Assistant Core 2026.9.0**. That floor provides the APIs
used by this patch. The automated development suite uses Core 2026.10.4 through
harness 0.13.375, the latest published harness reviewed on 6 November 2026.
Stable Core 2026.11.0 was covered by the maintainer's manual checks. Follow the
[support and release checklist](../development/contributing.md#home-assistant-support-and-release-review).

Back up Home Assistant, then upgrade through [Marketplace or HACS](../../README.md#marketplace-and-hacs-installation-recommended)
and restart. Keep the existing integration entry and statistics file. Older
coverage ranges are compacted on load and saved at the next checkpoint.

## Validation and publication

The merged consolidation base `2340196` matches development build `b44335a`,
tested by the maintainer on Core 2026.11.0. Those checks covered Custom options,
area retention, cancellation, reload and restart continuity, and automatic
Forecast chart refresh. Build `56510f2` added the checkpoint fix. On that build
the maintainer confirmed SE3 forecasts and live readings resumed and energy and
cost totals continued after restart. Home Assistant logged a 606 ms Average
Power Today state update. The statistics file held 177,106 power coverage
ranges and was 59,540,104 bytes.

With the compaction fix, the full local suite passed 1,498 tests each on Core
2026.9.0 and 2026.10.4, including legacy restore and gap preservation tests. In
a local synthetic benchmark of 177,106 continuous samples, the serialized pair
of histories went from 55.5 MB to about 24 KB. The median time for three
average-power calculations went from 90.8 ms to 0.36 ms, with the same result.

The maintainer installed build `4185146` on Core 2026.11.0 with the existing
snapshot in place. Configuration validation passed, readings resumed after restart,
and the log showed no errors or warnings. After a routine checkpoint, the
statistics file shrank from 59,540,104 to 40,015 bytes and power coverage went
from 177,106 to 17 ranges. After reloading the integration, readings resumed
and energy and cost totals continued without resets or jumps.

The [manual validation record](../validation/post-v1.7.md) identifies the results
and the deferred scenarios. [Issue #335](https://github.com/guslund-jpg/electricity-pro/issues/335)
tracks real solar and battery hardware validation.

Routine checkpoints can leave roughly one minute of cost and observation
updates in memory at the time of an abrupt stop, assuming successful writes.
See [statistics checkpoints](../guides/recorder.md#electricity-pro-statistics-checkpoints)
for recovery behavior.

The candidate checks passed for [#364](https://github.com/guslund-jpg/electricity-pro/pull/364).
The merged integration files match build `4185146`. The maintainer approved
publication on 6 November 2026.
