# Electricity Pro v1.7.0 — draft release and upgrade notes

**Candidate prepared, not published or approved for publication.** v1.6.0 remains the
stable release. These notes describe the proposed validation and maintenance
release, not new solar/battery or flexible-load capabilities.

## Upgrade requirement

**Home Assistant Core 2026.9.0 or newer is required. Upgrade Home Assistant
before installing Electricity Pro v1.7.0.** If you cannot upgrade Core, remain
on Electricity Pro v1.6.0, whose declared minimum is 2025.9.0.

The new floor permits native Probatio validation and removes the obsolete
schema compatibility adapter and minimum-test dependency workaround. Saved
settings, entity identities and storage formats are intended to remain intact.
The Home Assistant minimum will be reviewed for every release, not automatically
advanced on a schedule.

## Proposed release scope

- Expand strict type checking across 32 explicitly selected modules, including
  setup/options, provider inputs, pricing, forecasts, sensor metadata and
  coordinator data boundaries. This does not mean the entire repository is
  strictly typed; remaining framework/persistence exceptions are documented in
  the [contribution guide](../development/contributing.md).
- Reject malformed forecast prices, area/unit metadata and stored-history
  shapes explicitly while preserving valid calculations and saved formats.
- Remove `update_interval` polling from the Enhanced dashboard market forecast
  chart to address the observed ApexCharts Card 2.2.3 initialization stall.
  Source-entity updates drive the chart; its Now marker moves when it updates.

Existing copied dashboards are not rewritten by integration upgrades. Apply the
same removal to the market forecast chart or copy the updated
[dashboard example](../../examples/dashboards/README.md).

See [v1.7.0 candidate changes](../../CHANGELOG.md#170) for the detailed changes.
The [v1.6 validation limitations](1.6.0.md#explicit-release-boundaries) still
apply: synthetic tests do not establish real inverter/battery compatibility,
complete site balances, historical billing correction or safe device control.
Architecture issue #288 is follow-up work, not a blanket blocker for this scope.
