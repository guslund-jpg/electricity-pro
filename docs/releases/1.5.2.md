# Electricity Pro 1.5.2 — Startup Timezone Fix

A focused maintenance release based on v1.5.1, addressing feedback from the
[HACS catalogue review](https://github.com/hacs/default/pull/10261).

## Fix

The integration now reuses Home Assistant's already-loaded timezone during
setup and reload. It no longer constructs a timezone from its name in the
coordinator or price provider, avoiding potential timezone-database disk reads
on Home Assistant's event loop.

The configured timezone still governs local day/month boundaries and tariff
schedules, including daylight-saving transitions. No configuration migration,
meter reset or historical recalculation is introduced.

## Upgrade

1. Take a Home Assistant backup.
2. Install v1.5.2 and restart Home Assistant.
3. Confirm Electricity Pro loads, existing readings remain available, and
   there are no Electricity Pro timezone-related blocking-call warnings.

No settings or dashboard changes are required when upgrading from v1.5.1.
For earlier versions, also read the [v1.5.1 upgrade notes](1.5.1.md).

This release deliberately excludes the unreleased v1.6 production/export,
household-demand, compatibility, VAT-suggestion and Tibber-addition-estimate
features. If you manually installed development code, returning to this stable
release means those development-only features will not be available; retain a
backup before switching.

## Validation

- Regression tests verify setup and reload reuse Home Assistant's timezone for
  UTC, Stockholm, Helsinki and Oslo, without calling either former constructor.
- Existing tariff, local-day and daylight-saving tests use Home Assistant's
  timezone-setting API and retain their original behavioural assertions.
- The maintenance test suite passes: 570 tests.

This release addresses requested changes; it does not itself mean HACS default
catalogue acceptance. Acceptance remains subject to maintainer review.
