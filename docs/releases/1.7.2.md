# Electricity Pro v1.7.2 release and upgrade notes

v1.7.2 is a maintenance update to configuration and presentation. It organizes
existing settings into shared Custom/Tibber screens, adds reviewed Swedish
entity names and dashboard examples, and preserves the existing calculation,
accounting and saved-data contracts. The
[GitHub releases](https://github.com/guslund-jpg/electricity-pro/releases/latest)
identify the published stable version independently of the source version.

## Changes

- Share Measurements, Nord Pool, Electricity supplier, Grid charges,
  Production/export and Usage insights screens between both setup paths and
  Configure. A read-only Overview lets users review the assembled settings.
  Section saves preserve unrelated settings, explicit clears and zero values.
  (#373, #374–#380)
- Add reviewed Swedish display names for all 49 sensors and the Good Time
  binary sensor. Keep English fallback and the established default ID bases;
  preserve existing IDs, unique IDs and custom display names. (#289, #370–#372)
- Refine Swedish panel, menu, overview and entity wording after the maintainer's
  [bilingual review](../validation/translation-review-sv.md). (#383)
- Add Swedish Standard and Enhanced dashboard examples. Use Spot price in the
  English examples and Spotpris in Swedish. Translate Price direction's display
  states while keeping raw `rising`, `falling` and `stable` values. (#381, #382)
- Verify an existing ID-based automation before translated names are adopted,
  after adoption and after integration reload, with both default and customized
  entity identities. (#384)
- Clarify Recorder guidance for installations using SD cards. (#369)

Primary configuration sections and entity resources have English/Swedish text.
Some helper/error and retained legacy-form text still uses English fallback;
the review inventory identifies those gaps. Finnish was used to verify English
fallback, not to validate a Finnish translation. Additional languages remain
future reviewed translation work.

## Home Assistant support and compatibility review

Retain **Home Assistant Core 2026.9.0** and Python 3.14 as the minimum. This
maintenance scope introduces no API requiring a newer Core version. HACS metadata,
the minimum-Core pin and Python tooling retain that floor.

The release review on **7 November 2026** found stable Core
[2026.11.0](https://github.com/home-assistant/core/releases/tag/2026.11.0).
[PyPI](https://pypi.org/project/pytest-homeassistant-custom-component/) still lists
test harness **0.13.375**, targeting Core **2026.10.4** in its
[metadata](https://pypi.org/pypi/pytest-homeassistant-custom-component/json).
Retain that development baseline and the isolated 0.13.363 / Core 2026.9.0
minimum baseline. Full automated integration coverage on Core 2026.11 remains
pending; maintainer UI/runtime checks and the minimal stable-HA configuration
workflow are separate evidence.

The native Probatio schema path already shipped in v1.7.0. Retain the former
setup-submission paths, saved-area resolution and saved-settings overlay: they
protect callers and saved data, independently of the Core minimum. This patch
does not justify removing another HA-version compatibility adapter. See the
[per-release support review](../development/contributing.md#v172-review--7-november-2026).

## Upgrade and dashboards

After publication, upgrade through Marketplace or HACS and restart Home
Assistant. Keep the existing integration entry and statistics file. Review
settings through **Configure**; section saves keep the other sections intact.
Existing measurements, prices, histories and accumulated totals continue to use
their established keys and identities.

Entity display language follows the Home Assistant profile language. Names may
change to Swedish while entity IDs stay the same. User-defined names remain
authoritative. Existing automations should keep using entity IDs and raw state
values rather than translated display text.

Dashboard YAML is copied separately: an integration upgrade does not rewrite
an existing dashboard. Choose either English or Swedish for
[Standard or Enhanced](../../examples/dashboards/README.md#language-versions),
copy the complete example and check its entity references. Enhanced still
requires Mushroom and ApexCharts Card; Standard uses built-in cards.
