## Draft release notes: implemented on main

### Optional measured energy flows

- Separate AC production, directional grid-export and non-storage household
  demand power inputs, with partial daily/monthly energy totals derived from
  their respective lifetime registers.
- Independent counter protection across temporary dips, unavailable sources
  and restarts. A confirmed per-channel meter-replacement action preserves
  known totals while accepting a genuinely replaced meter's new baseline.
- Automatic installation-facts review after optional-source configuration.
  Unknown answers are accepted; the power compatibility diagnostic remains
  optional and defaults off for new configurations. Saved choices are retained.
- The diagnostic checks declared source conventions, validity, freshness and
  receipt-time alignment. An aligned result does not establish a complete site
  balance, sensor accuracy or billing accuracy.
- Optional production, export and household groups in both example dashboards.
  Dashboard YAML must be updated separately; integration updates do not rewrite
  a user's dashboard.

Import-only users do not need to configure these sources. Tibber fast-track
setup remains separate from the optional flow configuration. See
[source requirements](../guides/production-export.md) and
[compatibility checks](../guides/flow-compatibility.md).

### Pricing configuration and reliability

- Editable Nordic VAT suggestions, with automatic prefilling where a known
  Nord Pool area provides an unambiguous country hint. Saved rates are preserved;
  location/supply exceptions require confirmation rather than assumptions.
- Optional, reviewed Tibber-to-Nord-Pool forecast-addition estimation. It uses
  matching completed intervals and explicit VAT/area information, not a claim
  about the supplier's contractual fee breakdown. Tibber live prices are unchanged.
- Improved configuration-error recovery and forecast clock/retry handling.
- Full Python test execution in CI, a lint/type-check baseline and bounded
  internal refactors intended to preserve existing entity identities and behaviour.

See [VAT and forecast pricing](../guides/vat-pricing.md),
[forecast retrieval](../reference/forecast-retrieval.md) and the
[changelog](../../CHANGELOG.md) for details.

## Explicit release boundaries

Optional energy-flow features remain **experimental / not hardware-verified**
unless a separate, consented hardware-beta record establishes narrower verified
claims. Synthetic tests exercise software behaviour, not real inverter semantics.

This proposed release does not provide:

- Calculated whole-home balances, solar attribution, self-consumption or
  self-sufficiency ratios, or export revenue.
- Battery charge/discharge control, storage scheduling or verified GoodWe support.
- Guaranteed bill matching, complete historical backfill, or correction of old
  readings merely by installing an update.
- Appliance deadlines, EV target-charge guarantees or automatic device control.

Forecast scheduling prices include only their declared/configured components.
Cheapest windows minimize a duration-weighted price average; they do not model
an appliance's varying consumption through its cycle or guarantee that a chosen
window is below an absolute price ceiling.

### Automation examples

The separately installed [automation examples](../../examples/automations/README.md)
now provide a one-shot reminder for a selected cheapest 1h/2h/3h window and an
explicit appliance-action dry run. They preserve the accepted start/end/price,
require a currency and average-price ceiling, cancel revised windows before
start and refuse missed starts. Restarts and reloads require a new request.
Nothing installs through HACS or controls a real device by default.

Complementary examples provide a daily best-currently-available forecast notice,
a next-inexpensive-hour reminder and an opt-in Good Time/humidity simulation.
The simulation checks humidity changes, separate start/stop thresholds, minimum
off time, local reporting age and recovery; it changes only helpers and notifications,
not a real dehumidifier. The daily message does not assume tomorrow's prices arrived.

HA script-engine tests cover requests, local reporting-age checks, source loss,
revisions, duplicate requests, cancellation, shutdown and reload behaviour.
Maintainer-reported manual reminder and humidity simulation checks now cover
delivery, cancellation, restart/reload behaviour, price/currency guards,
hysteresis, cooldown, source loss and staleness; see the validation record for
the exact checks and remaining gaps. Physical-device testing remains unverified. The local
reporting-age check does not verify a fresh upstream forecast fetch. Review that
limitation before any device-specific adaptation; do not treat a smart plug as
a safe generic appliance start action. EV control is deferred, with guidance
only, until persistent job/stop handling and charger-specific checks are tested.

The existing window sensors do not offer a finish-by deadline or EV state-of-charge
target. More general appliance optimisation remains future scope. Reusable
blueprints can follow after the examples and their safety boundaries are tested.

### Smoothed forecast price trend — changed existing entity

`price_direction` now compares duration-weighted scheduling-price averages for
[now, +1 hour) and [+1 hour, +2 hours), rather than two individual intervals.
Its entity identity is retained; no second trend sensor is added. Both dashboards
label it "Price trend — next 2 hours". Existing user dashboards need their YAML
updated separately.

Stable means the absolute difference is at most 2% of the larger absolute hourly
average. This symmetric relative tolerance works with negative prices and any
currency scale; there is no currency-specific floor near zero or stateful
hysteresis. Partial intervals and configured tariff changes are duration weighted
using UTC elapsed time, including midnight/DST transitions. Gaps, insufficient
coverage or incompatible scope leave the sensor unavailable. Complete time
coverage does not imply complete bill components.

**Behaviour/attribute change:** personal automations must no longer interpret the
state as next-quarter direction. Interval attributes are replaced by explicit
hour boundaries and hourly averages, with delta and tolerance exposed. See the
[sensor contract](../reference/sensors.md#price-trend--next-2-hours-unreleased-v16).
Good Time, costs and cheapest windows do not depend on this result and are unchanged.
Automated checks cover the new contract. On November 1, the maintainer confirmed
the existing entity's new hourly attributes, a correctly classified rising
example and advancing hour boundaries after 20 minutes on the synthetic HA
with a real Nord Pool SE3 forecast. Dashboard presentation remains to be reviewed.

## Draft upgrade guidance

Back up Home Assistant and record the currently installed version/commit first.
For a manually copied development build, the displayed 1.5.1 manifest version
does not identify its source revision. Keep a rollback copy outside the loaded
custom-components directory.

Install the approved release and restart. Preserve the existing configuration
entry and verify source bindings, pricing settings, Good Time behaviour and logs
before relying on device-control automations. Do not initialize a test package,
reset a meter or clear accounting history as an upgrade step.

Optional flow sources are configured separately after import-only checks. Select
only sources whose documented meanings match the input contract; a label such
as "load" is not proof that battery charging is excluded. Existing manually
copied dashboards need a separate update to display new optional groups.

The synthetic package is for a disposable test instance only and is not part of
normal installation. Draft notes must not instruct ordinary users to install it.
