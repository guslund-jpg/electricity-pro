# v1.1 Implementation Checklist

> Delivery checklist for forecast prices and scheduling insights based on the [v1.1 design proposal](./v1.1-forecast-prices-and-scheduling-insights.md).

---

## 1. Forecast data foundation

- [x] Identify the exact Nord Pool future-price source available through Home Assistant.
- [x] Confirm that the native Nord Pool integration uses split entities plus the `nordpool.get_prices_for_date` action instead of exposing raw interval lists on the main current-price sensor.
- [x] Confirm that the action returns interval `start`, `end` and `price` fields, with timestamps in UTC and prices in requested currency per MWh.
- [ ] Define the internal normalized forecast interval structure.
- [ ] Decide where forecast ingestion should live relative to the existing provider and coordinator modules.
- [ ] Decide whether restart persistence is required or whether source rehydration is sufficient.

---

## 2. Forecast normalization

- [ ] Parse action-returned future intervals into timezone-aware start and end datetimes.
- [ ] Derive interval resolution from interval boundaries instead of assuming hourly data.
- [ ] Normalize raw market price, currency, area and publication timestamp.
- [ ] Convert source prices from currency per MWh to currency per kWh before calculations.
- [ ] Reject or ignore malformed intervals according to documented behavior.
- [ ] Discard expired intervals before scheduling calculations run.
- [ ] Detect gaps and overlaps explicitly.

---

## 3. Effective future price calculation

- [ ] Reuse the existing pricing adjustment philosophy for effective future prices.
- [ ] Produce both raw market price and effective price in the normalized interval model.
- [ ] Verify behavior when variable fee and markup options are absent.
- [ ] Verify behavior when configured adjustments are present.

---

## 4. Insight calculations

- [ ] Implement cheapest upcoming single-interval calculation.
- [ ] Implement cheapest continuous multi-interval window selection for the initial supported durations.
- [ ] Implement next inexpensive window detection relative to a configured threshold.
- [ ] Implement simple near-term price direction classification.
- [ ] Ensure calculations depend only on normalized intervals.
- [ ] Return unavailable results when required future data is missing or incomplete.

---

## 5. Home Assistant integration

- [ ] Decide which forecast outputs become sensors and which details live in attributes.
- [ ] Add forecast and scheduling insight entities.
- [ ] Ensure entity names, unique IDs and device metadata follow project conventions.
- [ ] Recompute insights when forecast intervals change.
- [ ] Recompute insights when pricing adjustment options change.
- [ ] Ensure stale insights expire correctly as time advances.

---

## 6. Time and lifecycle behavior

- [ ] Validate local timezone handling across all interval calculations.
- [ ] Cover daylight-saving transitions with focused tests.
- [ ] Confirm behavior when `binary_sensor.nord_pool_<area>_tomorrow_price_available` and `nordpool.get_prices_for_date` disagree or change at different times.
- [ ] Confirm behavior when Nord Pool tomorrow data is delayed or partially published.
- [ ] Confirm restart behavior and data refresh flow.
- [ ] Avoid unnecessary polling if Home Assistant source updates and native Nord Pool action availability are sufficient.

---

## 7. Testing

- [ ] Add unit tests for interval normalization.
- [ ] Add unit tests for gap and overlap handling.
- [ ] Add unit tests for continuous-window selection.
- [ ] Add unit tests for effective future-price adjustments.
- [ ] Add unit tests for daylight-saving and timezone edge cases.
- [ ] Add integration tests for Home Assistant entity updates from Nord Pool forecast changes.
- [ ] Add integration tests for unavailable forecast states.

---

## 8. Documentation and release preparation

- [ ] Update user-facing documentation to state that v1.1 forecast features require Nord Pool.
- [ ] Document any new configuration options and dashboard examples.
- [ ] Add release notes for forecast prices and scheduling insights.
- [ ] Confirm roadmap, README and design docs remain aligned.
- [ ] Run the relevant project validation before release.
